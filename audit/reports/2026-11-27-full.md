Проект целостен как исследовательский кабинет: явный расчёт в `signs.ts` / `norms.ts` / `curve.ts` без ИИ внутри формулы, сборка и typecheck зелёные, секреты в git не торчат, `preview.py` слушает только localhost и ограничивает proxy. Калибровочные долги (safe zone × вес, priors) совпадают с `TODO.md` и не выдаются за новые баги кода.

Как исследовательский инструмент опираться можно с оговорками `DISCLAIMER.md`; как на мед. изделие — нельзя (и проект этого не обещает).

## Находки

### H-01 Выписка «Анализы» в чате врача включает поля анкеты

- **Severity:** medium
- **Где:** `src/app/talk.ts` — `labsSnapshot` (~474–484), используется в `clientBrief` для шага `labs`
- **Что не так:** в блок попадают не только коды каталога анализов, но и любые значения с кодом `/^[A-Z][A-Z0-9_]*$/` (NAME, SEX, HEIGHT, VISIT_REASON…), дублируя Общее/Параметры и маскируясь под анализы (`NAME (NAME)=…`).
- **Доказательство:** условие `!Labs.has(code) && !/^[A-Z].../` — достаточно regex; воспроизведено в живом логе «запросы» (сессия аудита пользователя).
- **Риск:** модели неправильно интерпретируют контекст; шум и противоречия в system.
- **Как проверить после фикса:** открыть «Поговорить», «запросы» → в out под `## Анализы` только лабораторные коды; NAME/SEX отсутствуют. Уже в `TODO.md`.

### E-01 `qualSign`: POS слишком жадный

- **Severity:** medium
- **Где:** `src/app/labs.ts:33-41` (`POS` / `NEG`)
- **Что не так:** POS ловит `рост`, `да`, `есть`, `выявл` и т.п. NEG проверяется раньше (хорошо для «не обнаружено» / «нет роста»), но свободный текст вроде «есть жалобы» / «да, сдавал» теоретически может дать +1 («обнаружено») при qual-интерпретации.
- **Доказательство:** `POS = /(обнаруж|выявл|положит|рост|positive|…|^да$|^есть$)/i`.
- **Риск:** ложный вклад «вверх» для качественного признака на мусорном/повествовательном значении.
- **Как проверить после фикса:** юнит-тесты на граничные строки; в `strength` qual только для type=qual или явного разбора.

### B-01 Почти нет автотестов на ядро и кабинет

- **Severity:** medium
- **Где:** `tests/*.test.js` (фактически один тест статей), `package.json` scripts
- **Что не так:** `npm test` зелёный, но не проверяет `evaluate`/`strength`/`specificity`/`qualSign`/`syncFolder`/импорт единиц.
- **Доказательство:** вывод `tests 1 / pass 1`; в package только typescript.
- **Риск:** регрессии формулы и импорта незаметны до ручного прогона.
- **Как проверить после фикса:** добавить node:test на signs/labs; `npm test` падает на сломанной формуле.

### D-01 Широкая поверхность `innerHTML` в кабинете

- **Severity:** low
- **Где:** `src/app/app.ts`, `settings.ts`, `talk.ts`, `diagnoses.ts` (десятки `innerHTML`)
- **Что не так:** доминирует паттерн `esc()`, но объём шаблонов велик; полный XSS-аудит каждого вставления не выполнен. Чат пользователя экранирует `say`/ввод; лог запросов — через `esc` в HTML.
- **Доказательство:** grep `innerHTML` по `src/app`; выборочно пузыри чата с `esc(text)`.
- **Риск:** точечный XSS при пропуске `esc` на новом UI (ключи/анкета в DOM).
- **Как проверить после фикса:** чеклист новых `innerHTML`; опционально линтер/запрет без esc.

### I-01 `docs/help.html` отстаёт от кабинета

- **Severity:** info
- **Где:** `docs/help.html`; зафиксировано в `TODO.md` / `AGENTS.md`
- **Что не так:** help не описывает актуально провайдеры (OpenAI-совместимый), лог «запросы», помощников анкеты, связь разделов/врачей и т.д.
- **Доказательство:** TODO «Помощь на сайте»; AGENTS помечает help как отстающий.
- **Риск:** пользователь/аудитор путается в UI; не баг кода.
- **Как проверить после фикса:** пройти help рядом с кабинетом по чеклисту экранов.

### E-02 / I-04 Известные калибровочные долги (не баг кода)

- **Severity:** info
- **Где:** `signs.ts` SAFE_MAX×w; priors в `signs.json` (напр. «Метаболический синдром» prior=30)
- **Что не так:** поведение совпадает с описанием и TODO; клиническая истинность весов не оценивалась.
- **Доказательство:** `strength` обнуляет при k≤SAFE_MAX; prior 30 в данных.
- **Риск:** завышенные/заниженные P на демо-данных; ожидаемо для черновика.
- **Как проверить после фикса:** калибровка по TODO, не «починить evaluate втихую».

### C-01 Ключ Gemini в query string URL

- **Severity:** low
- **Где:** `src/app/models.ts` / `aicall.ts` — `generateContent?key=`
- **Что не так:** ключ уходит в URL (типично для Gemini); может попасть в логи прокси/историю, сильнее чем Bearer-заголовок.
- **Доказательство:** код fetch моделей/chat с `encodeURIComponent(c.apiKey)` в query.
- **Риск:** утечка ключа через логи посредника/расширения при включённом proxy.
- **Как проверить после фикса:** по возможности header/альтернативный auth; не логировать полный URL.
