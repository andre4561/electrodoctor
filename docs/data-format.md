# Форматы данных

Все таблицы — CSV в UTF-8, первая строка — заголовки.

## Таблица пациента (`examples/*.csv`)

Одна строка — одно значение («длинный» формат).

| Колонка | Смысл |
|---|---|
| code | код параметра из `data/parameters.csv` (или SEX, AGE) |
| value | число; для да/нет — 1 или 0 |
| unit | единица (для читаемости) |
| date | относительная дата: `day0`, `day+14` — без реальных дат |
| source | анализ / опрос / осмотр / паспорт |

**Нет строки = не спрашивали** (вклад 0). **Строка со значением 0 = точно нет** (штраф). Это разные вещи.

## `data/parameters.csv`

| Колонка | Смысл |
|---|---|
| code | уникальный код, ЗАГЛАВНЫМИ, `_` между частями |
| type | `continuous` (анализы, измерения), `binary` (да/нет), `ordinal` (шкала) |
| x0, w, scale, a_low, a_high | параметры параболы — только для `continuous` |
| max | максимум шкалы — для `binary` (1) и `ordinal` |

### Правила кодов для жалоб и осмотра

`<ПРИЗНАК>_<АТРИБУТ>` по схеме: локализация, иррадиация, характер, интенсивность, длительность, условия появления и облегчения.

- `PAIN_CHEST` — есть ли боль в груди
- `PAIN_CHEST_PRESSING` — характер (каждый вариант — свой параметр)
- `PAIN_CHEST_IRRAD_LARM` — иррадиация в левую руку
- `PAIN_CHEST_NRS` — интенсивность по шкале 0–10
- `PAIN_CHEST_EXERTION` — условие появления

Где есть проверенная шкала (боль 0–10, NYHA, отёки 0–3+, Глазго), используем её.

## `data/diagnoses.csv`

`code` (МКБ-10), `name`, `prior` (исходная частота, доля 0–1), `source`.

## `data/links.csv`

| Колонка | Смысл |
|---|---|
| diagnosis, param | пара «диагноз–показатель» |
| expected | ожидаемое направление: `down` / `up` (для да/нет — `up`) |
| weight | вес при отклонении; отрицательный = признак против диагноза |
| penalty | вклад, если показатель в норме / признака нет |
| source | откуда взят вес (ссылка, DOI или `expert`) |

## `data/directions.csv`

`diagnosis`, `direction` — связь многие-ко-многим.

## Анализы из ИИ (`electrodoctor-labs`)

Кабинет не распознаёт фото сам. Человек копирует промпт (вкладка «Анализы» → «Загрузить анализы через ИИ»), отправляет его вместе с фото в любой ИИ и вставляет ответ обратно. Промпт собирается из `src/app/fields.ts`, поэтому список кодов в нём всегда совпадает с анкетой.

```json
{
  "format": "electrodoctor-labs",
  "version": 1,
  "date": "2026-10-20",
  "lab": "название лаборатории",
  "results": [
    { "code": "HGB", "name": "Гемоглобин", "value": 118, "unit": "г/л", "ref": "120–150", "uncertain": false }
  ]
}
```

| Поле | Смысл |
|---|---|
| code | код поля анкеты; `null`, если подходящего нет |
| name | название, как на бланке |
| value | число с точкой; для полей с вариантами — один из вариантов; «<5» и текст — строкой |
| unit | единица с бланка |
| ref | референсный интервал с бланка или `null` |
| uncertain | `true`, если цифра читается плохо |

Перед переносом кабинет показывает таблицу для проверки. По умолчанию не отмечены: значения с другими единицами, неуверенные значения и повторы одного кода. Всё, чему нет своего поля (нет кода, не число, нет такого варианта), уходит строкой в «Другие показатели». Разбор — `src/app/aiimport.ts`.
