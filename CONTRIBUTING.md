# Как участвовать

## Предложить вес для пары «диагноз–показатель»

Откройте issue или pull request с правкой `data/links.csv`. Для каждой строки нужны:

- код диагноза (МКБ-10) и код показателя из `data/parameters.csv`;
- ожидаемое направление отклонения (`down` / `up`);
- вес и штраф;
- **источник**: клиническая рекомендация, статья, руководство (ссылка или DOI) в колонке `source`.

Без источника вес принимается только с пометкой `expert` в колонке `source` и ваших данных о специальности.

Если в источнике есть чувствительность и специфичность признака, приложите их: из них вес считается точнее, чем «на глаз».

## Добавить диагноз

1. Строка в `data/diagnoses.csv`: код МКБ-10, название, исходная частота с источником.
2. Строки в `data/directions.csv`: к каким направлениям относится (можно к нескольким).
3. Строки в `data/links.csv`: 3–15 самых значимых показателей.
4. Если нужны новые показатели — строки в `data/parameters.csv`.
5. Желательно: учебный пациент в `examples/` и тест в `tests/`.

## Добавить показатель

Правила кодов и типов — в [docs/data-format.md](docs/data-format.md). Для жалоб и осмотра по возможности используйте проверенные шкалы (боль 0–10, NYHA, отёки 0–3+) и сверяйтесь с терминологией SNOMED CT.

## Код

- Эталонная реализация в `engine/electrodoctor.py` намеренно простая и без зависимостей. Ясность важнее скорости.
- Любое изменение расчёта сопровождается тестом.
- `python -m unittest discover tests` должен проходить.
- Расчёт для сайта и приложений — `src/engine.ts`. Меняете формулу — меняйте её и в Python, и в TypeScript; `npm test` сверит обе версии.
- Файлы `docs/*.js` и `docs/app/*.js` собираются из `src/` командой `npm run build` — правьте `.ts`, а собранный `.js` коммитьте вместе с ним.

## Чего не присылать

Реальные данные пациентов, даже «обезличенные вручную». Только вымышленные примеры.
