# Форматы данных

Актуальные данные расчёта кабинета — JSON в `docs/data/`. Собираются конвейером
`tools/` (см. `AGENTS.md`); руками править нежелательно. Правки человека в кабинете
хранятся в настройках и перекрывают файлы.

Старый черновик на CSV (`data/*.csv`, `engine/`) в репозитории больше не используется.

## Каталог анализов (`docs/data/labs.json`)

`format`: `electrodoctor-labs`. Поле `items`: код → описание.

| Поле | Смысл |
|---|---|
| name | название |
| aliases | синонимы (поиск, распознавание ИИ) |
| type | `number` (норма), `qual` (наличие), `text` |
| unit | единица |
| group | раздел по материалу, напр. `Кровь — биохимия` |
| inForm | есть ли в стандартном бланке анкеты (`fields.ts`) |
| article | имя статьи в `docs/articles/lab-tests/` без `.md` (запасной вариант; основной словарь — `src/app/articles.ts`) |
| refs | у скольких диагнозов анализ в признаках (сводка сборки) |

Новый код в кабинете: Настройки → Нормы и веса → «+ Добавить анализ» (`settings.labs`).

## Нормы и кривые (`docs/data/norms.json`)

`format`: `electrodoctor-norms`. `items`: код анализа → норма и кривая критичности.

| Поле | Смысл |
|---|---|
| norm | норма одним числом (точка 0% кривой) |
| range | типичный интервал для справки |
| note | пояснение (пол, возраст…) |
| curve.L / curve.R | левый и правый край отклонения в % (`L < 0 < R`) |
| curve.pts | точки `[x, критичность]`; x — доля края (−1…+1) |
| curve.linear | `true` — прямые между точками, иначе сплайн PCHIP |

Предложения ИИ: `tools/ai_norms.py` → `tools/norms_apply.py` (в файл без ручного ревью).
В кабинете нормы/кривые можно переопределить глобально (Нормы и веса) или у клиента.

## Признаки диагнозов (`docs/data/signs.json`)

`format`: `electrodoctor-signs`. Ключ в `items` — **имя файла статьи** в
`docs/articles/diagnoses/` без `.md` (не код МКБ).

```json
{
  "prior": 2,
  "labs": [{ "code": "CRP", "dir": "up", "w": 7, "normal": "lower" }],
  "exam": [{ "name": "Лихорадка", "w": 8, "note": "≥38 °C" }],
  "instr": [{ "name": "ЭКГ: подъём ST", "w": 9 }],
  "nolist": [{ "name": "Тропонин высокочувствительный", "code": "TROPONIN", "dir": "up", "w": 8 }]
}
```

| Поле | Смысл |
|---|---|
| prior | распространённость в **процентах** (не в долях) |
| labs[].code | код из каталога / бланка |
| labs[].dir | `up` / `down` / `any` |
| labs[].w | важность 0–10 |
| labs[].normal | `lower` — в норме снижает вероятность |
| exam / instr | текстовые признаки осмотра и инструментальных находок |
| nolist | нужный анализ не из бланка; опционально `code` справочника |

Формула — `src/app/signs.ts`. Свои признаки в настройках перекрывают файл.

## Разделы диагнозов (`docs/data/diagnoses.json`)

`format`: `electrodoctor-diagnoses`. Собирает `tools/diagnoses_sections.py` по тегам статей.

- `sections[]` — id, title, desc, tags
- `flags[]` — пометки (неотложно, дети…)
- `items` — имя статьи → `{ title, sections[], flags? }`

## Описания осмотра (`docs/data/exam-descs.json`)

Тела признаков для кабинета (Настройки → Осмотр). Статьи — `docs/articles/exams/*.md`.

## Ответ ИИ с бланка анализов (`electrodoctor-labs`)

Тот же `format`, но это **ответ распознавания**, не файл каталога. Кабинет строит промпт
(вкладка «Анализы» → загрузка через ИИ) и разбирает JSON (`src/app/aiimport.ts`).

```json
{
  "format": "electrodoctor-labs",
  "version": 1,
  "date": "2026-10-20",
  "lab": "название лаборатории",
  "results": [
    { "code": "HGB", "name": "Гемоглобин", "value": 118, "unit": "г/л", "ref": "120–150", "uncertain": false }
  ]
}
```

| Поле | Смысл |
|---|---|
| code | код поля / каталога; `null`, если не нашелся |
| name | как на бланке |
| value | число или текст / вариант |
| unit | единица с бланка |
| ref | референс с бланка или `null` |
| uncertain | `true`, если цифра читается плохо |

Перед переносом — таблица проверки. Несовпадение единиц и неуверенные значения по
умолчанию не переносятся без подтверждения.
